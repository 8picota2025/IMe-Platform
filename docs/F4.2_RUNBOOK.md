## Idempotencia de pago (`claimPaidTransition`)

Varios caminos pueden confirmar el mismo pedido como `pagado` (webhook Wompi duplicado, reconciliación en `consultar-pedido`, race entre webhook y polling del cliente). Los efectos secundarios — consumo de reservas, email al cliente, dropship, sync CRM — deben ejecutarse **una sola vez**.

### Mecanismo

Helper compartido: `src/lib/payment-state.ts` → `claimPaidTransition(client, pedidoId)`.

```sql
UPDATE pedidos SET estado = 'pagado'
WHERE id = :pedidoId AND estado <> 'pagado'
RETURNING id;
```

- `claimed: true` → este caller ganó la transición; ejecutar `registrarPedidoPagado` + `notificarFulfillmentDropship`.
- `claimed: false` → otro proceso ya marcó `pagado`; responder 200 al webhook pero **no** repetir side effects.

### Callers actuales

| Función            | Cuándo reclama                                      |
| ------------------ | --------------------------------------------------- |
| `webhook-wompi`    | Tras `verificarPago` server-side → `pagado`           |
| `consultar-pedido` | Reconciliación Wompi cuando el cliente consulta estado |

`eventos_pago` sigue deduplicando por `(proveedor_pago, event_id)` antes de tocar el pedido.

### Stripe (gap conocido)

`webhook-stripe` aún **no** usa `claimPaidTransition`. Si llegan dos eventos `checkout.session.completed` válidos en paralelo, `registrarPedidoPagado` podría ejecutarse dos veces. Prioridad: alinear Stripe con el mismo patrón que Wompi.

### Troubleshooting

| Síntoma                                      | Qué revisar                                                                 |
| -------------------------------------------- | --------------------------------------------------------------------------- |
| Cliente pagó pero pedido sigue `pendiente`   | Logs `webhook-wompi`; fila en `eventos_pago`; reconciliar vía `consultar-pedido` |
| Doble email / doble notificación proveedor   | Buscar dos filas `eventos_pago` distintas con mismo `referencia_pasarela`; verificar si `claimPaidTransition` corrió |
| Webhook 200 pero sin dropship                | `claimed: false` (ya pagado) o `fulfillment_mode` ≠ `dropship`              |
